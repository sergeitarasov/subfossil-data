# Original stacked photographs

These files are the unmodified `*ZS PMax.jpg` stacked photographs selected from the OneDrive `General/subfossil_pictures` collection. Camera frames and stacking-project files are not included. The image bytes have not been resized, recompressed, cropped, or otherwise edited.

Layout: `data/original/<island>/<body-part>/<voucher-ID>.jpg`. `MAU` denotes Mauritius and `ROD` denotes Rodrigues. Body-part directory names are retained from the source, including `head_pronotum` for an associated head/pronotum preparation.

Prepared on 2026-10-05 from the previously verified local copies. All 1,658 reorganized files were checked against their pre-move SHA-256 hashes. OneDrive originals were not modified. This check does not verify the separate Allas backup.

## Source and naming procedure

The selection and voucher naming follow the existing `Subfossils/pyImaging/copyImages.py` workflow: select the stacked JPEG inside a voucher folder and name it after the voucher. Unlike that script, this collection preserves multiple matches rather than overwriting a previous image.

The source root is the university OneDrive `General/subfossil_pictures`. Paths in this README are relative to that source root or to this `data/original` directory, as labelled. For a standard single-image record, its former path was `<island>/<body-part>/<voucher-ID>/<timestamp> ZS PMax.jpg`. The full per-file source mapping and checksums are in `image-manifest.json`.

The manifest provides provenance for all images, including the former timestamps and the exceptions listed above. No taxonomic assignment, anatomical view, laterality, or sample age was inferred by this reorganization.
